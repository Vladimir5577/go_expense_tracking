# Сервис учёта личных расходов

REST API на Go + SQLite. Пользователь заводит свои категории затрат, добавляет
траты и смотрит отчёты за день, неделю и месяц — в том числе по одной или
нескольким категориям.

Собирается в один бинарник без CGO: драйвер SQLite — `modernc.org/sqlite`.
Сервис сам отдаёт статику фронтенда из `WEB_DIR`, поэтому `./main` в одиночку —
это уже работающее приложение: ни nginx, ни dev-сервера не требуется. Docker тоже.

## Развёртывание

Для сервера — отдельная инструкция: [DEPLOY.md](DEPLOY.md). Там systemd либо
Docker на выбор, nginx с TLS, обновление версии, бэкапы и восстановление.
Ниже — локальный запуск.

### 1. Конфигурация

```bash
cp .env.example .env
```

Обязательно заполните `JWT_SECRET` — без него сервис не стартует:

```bash
openssl rand -hex 32
```

### 2. Сборка

```bash
go build -o main cmd/main.go && go build -o useradm cmd/useradm/main.go
```

### 3. Миграции

Накатываются goose снаружи (goose в зависимости проекта не входит):

```bash
goose -dir migrations sqlite3 ./data/expenses.db up
```

Установить goose, если его нет:

```bash
go install github.com/pressly/goose/v3/cmd/goose@latest
```

### 4. Первый пользователь

Регистрации через API нет — пользователи заводятся только из консоли:

```bash
./useradm create -login vladimir -name "Владимир"
```

Пароль запрашивается интерактивно и не отображается при вводе.

### 5. Запуск

```bash
./main
```

### 6. Фронтенд

Инструментарий сборки стилей живёт в `frontend/` и наружу не отдаётся. Tailwind
собирает `frontend/input.css` в `web/app.css`, который уже лежит в git — поэтому
для запуска Node не нужен, он нужен только если вы правите стили:

```bash
cd frontend && npm ci         # один раз, если правите стили
cd frontend && npm run css    # пересборка на каждое изменение, для разработки
```

Перед коммитом — минифицированная сборка:

```bash
npm --prefix frontend run css:build
```

Разметка и логика — обычные ES-модули без сборщика: правка `.js` подхватывается
обычной перезагрузкой страницы.

## Просмотр базы

Веб-интерфейс DBGate, поднимается отдельно и только когда нужен:

```bash
docker compose -f docker-compose.dbgate.yml up -d
```

Открыть http://localhost:8089, слева выбрать подключение «Расходы». Остановить:

```bash
docker compose -f docker-compose.dbgate.yml down
```

Два ограничения, о которых стоит знать:

- **Каталог с базой монтируется на запись, а не только на чтение.** SQLite
  в режиме WAL требует права записи на `-shm`-файл даже для простого чтения
  данных, и с `:ro` подключение не откроется.
- **UID контейнера должен совпадать с владельцем каталога** — по той же причине,
  что и у самого сервиса. Иначе DBGate наделает файлов от root и база станет
  недоступна с хоста.

DBGate не работает в мобильном браузере — с телефона базу посмотреть не выйдет.

Альтернатива без Docker — десктопное приложение:

```bash
sudo apt install sqlitebrowser && sqlitebrowser data/expenses.db
```

Смотреть можно и на работающем сервисе: WAL допускает читателей параллельно
с писателем. Если хочется совсем без рисков — снимите снимок и открывайте его:

```bash
sqlite3 data/expenses.db "VACUUM INTO '/tmp/snapshot.db'"
```

## API

Все ответы — JSON. Ошибки в едином формате `{"error": "...", "code": "..."}`.

| Метод | Путь | Описание |
|---|---|---|
| GET | `/healthz` | проверка живости, без авторизации |
| POST | `/api/auth/login` | вход, возвращает токен |
| GET | `/api/me` | текущий пользователь |
| GET | `/api/categories` | список категорий |
| POST | `/api/categories` | создать категорию |
| GET | `/api/categories/{id}` | получить категорию |
| PATCH | `/api/categories/{id}` | изменить категорию |
| DELETE | `/api/categories/{id}` | удалить (409, если есть траты) |
| GET | `/api/expenses` | список трат с фильтрами |
| POST | `/api/expenses` | добавить трату |
| GET | `/api/expenses/{id}` | получить трату |
| PATCH | `/api/expenses/{id}` | изменить трату |
| DELETE | `/api/expenses/{id}` | удалить трату |
| GET | `/api/reports/summary` | сумма за период по категориям |
| GET | `/*` | статика фронтенда из `WEB_DIR`, с фолбэком на `index.html` |

Всё, кроме `/healthz` и `/api/auth/login`, требует заголовок
`Authorization: Bearer <токен>`.

### Фильтры списка и отчёта

Оба эндпоинта принимают один и тот же набор параметров:

| Параметр | Значение |
|---|---|
| `period` | `day` \| `week` \| `month` — разворачивается в диапазон дат |
| `date` | опорная дата для `period`, по умолчанию сегодня |
| `from`, `to` | явные границы `YYYY-MM-DD`, включительные; важнее `period` |
| `categoryIds` | список через запятую: `1,3,7`, максимум 50 |
| `page`, `limit` | пагинация, `limit` 1..200 (по умолчанию 50); только для списка |

Список трат возвращает `totalItems` — это **количество записей**, подходящих
под фильтр. Сумма денег живёт только в отчёте, в поле `total`. Имена разные
намеренно: одинаковое имя для количества и для суммы — источник ошибок на клиенте.

Неделя начинается с понедельника. Какой день считается «сегодня» и где проходят
границы периодов — определяет `APP_TIMEZONE`.

### Примеры

```bash
# Вход
TOKEN=$(curl -s -X POST localhost:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"login":"vladimir","password":"пароль"}' | jq -r .token)

# Категория
curl -X POST localhost:8080/api/categories \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"Продукты","description":"Еда и бытовая химия","color":"green"}'

# Трата (spentAt можно не указывать — подставится сегодняшняя дата)
curl -X POST localhost:8080/api/expenses \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"categoryId":1,"amount":1543.20,"description":"Пятёрочка","spentAt":"2026-08-24"}'

# Траты за неделю по двум категориям
curl "localhost:8080/api/expenses?period=week&categoryIds=1,2" \
  -H "Authorization: Bearer $TOKEN"

# Отчёт за месяц
curl "localhost:8080/api/reports/summary?period=month" \
  -H "Authorization: Bearer $TOKEN"
```

Ответ отчёта:

```json
{
  "from": "2026-08-01",
  "to": "2026-08-31",
  "total": 11751.11,
  "byCategory": [
    {"categoryId": 1, "name": "Продукты",  "total": 4880.36, "count": 4, "share": 41.53},
    {"categoryId": 2, "name": "Транспорт", "total": 3770.75, "count": 3, "share": 32.09}
  ]
}
```

### Коды ошибок

| Код | Статус | Когда |
|---|---|---|
| `invalid_json` | 400 | тело запроса не разбирается |
| `validation_failed` | 400 | не прошли валидацию поля или параметры фильтра |
| `unauthorized` | 401 | нет токена, токен просрочен или подпись не сходится |
| `invalid_credentials` | 401 | неверный логин или пароль |
| `too_many_attempts` | 429 | вход по этому логину временно заблокирован |
| `category_not_found` | 404 | категории нет либо она чужая |
| `expense_not_found` | 404 | траты нет либо она чужая |
| `category_name_exists` | 409 | имя категории уже занято у этого пользователя |
| `category_has_expenses` | 409 | на категории висят траты, удалять нельзя |
| `internal_error` | 500 | внутренняя ошибка, подробности в логе сервиса |

## Фронтенд

Одностраничное приложение на чистом JavaScript, mobile-first: вносить траты
будут с телефона, десктоп — тот же макет в одну колонку.

Каталог `web/` содержит ровно то, что сервис отдаёт браузеру. Всё, что браузеру
не нужно — сборщик стилей, его зависимости и исходник CSS, — лежит в `frontend/`
и наружу не попадает.

```
frontend/          инструментарий, на сервер не едет
  package.json
  package-lock.json
  input.css        исходник стилей: тема Tailwind и повторяющиеся компоненты

web/               то, что отдаётся браузеру
  index.html
  app.css          собранный CSS (в git, чтобы деплой не требовал Node)
  js/
    api.js         обёртка над fetch: токен, разбор ошибок, реакция на 401
    format.js      деньги, даты, проценты, разбор введённой суммы
    colors.js      палитра категорий
    messages.js    коды ошибок API → тексты для пользователя
    store.js       состояние приложения и подписки
    router.js      хешевый роутер
    main.js        маршруты и точка входа
    views/
      layout.js    шапка и общие куски разметки
      login.js     экран входа
      expenses.js  главный экран: период, фильтр, сводка, список, форма
      categories.js управление категориями
```

Три экрана: вход, траты, категории. На главном — переключатель день/неделя/месяц,
фильтр по категориям чипами, сводка с полосой долей, список трат, сгруппированный
по датам, и форма добавления. Тап по строке открывает её на редактирование.

### Решения фронтенда

**Границы периодов считает сервер.** Клиент шлёт `?period=week` и не содержит
ни строчки арифметики по датам — это убирает целый класс расхождений между
клиентом и сервером.

**Разделение под будущий переезд на React.** `api.js`, `format.js`, `colors.js`
и `messages.js` — чистые функции без DOM, они переносятся без правок. `views/`
выбрасывается и переписывается компонентами; чтобы это было механической
работой, во вьюхах нет ни одного `fetch` и никаких вычислений — только
`данные → разметка`. Классы Tailwind переезжают в JSX дословно.

**Никакой самописной реактивности.** Изменилось состояние — секция
перерисовывается целиком через `innerHTML`. Это то место, где легко построить
мини-React, который потом пришлось бы выпиливать.

**Токен в `localStorage`.** Уязвим к XSS; альтернатива — httpOnly-кука — требует
защиты от CSRF и правок сервера. Для сервиса без сторонних скриптов на странице
выбран первый вариант.

**Экранирование.** Названия категорий и описания трат вводит пользователь, а
вставляются они через `innerHTML` — всё пользовательское проходит через
`escapeHtml` из `views/layout.js`.

**Палитра категорий перечислена literal-строками** в `colors.js`. Tailwind
собирает CSS, сканируя исходники на имена классов, и динамически собранное
``bg-cat-${key}`` в сборку не попадёт.

**Мобильные мелочи, которые видно только на телефоне:** `inputmode="decimal"` на
поле суммы (цифровая клавиатура), базовый размер шрифта полей 16px (иначе Safari
на iOS зумит страницу при фокусе), тапы не меньше 44px, `env(safe-area-inset-bottom)`
в отступах, `min-h-dvh` вместо `min-h-screen`.

## Как устроено

```
cmd/main.go            точка входа сервиса
cmd/useradm/main.go    консольное управление пользователями
migrations/            SQL-миграции (goose)
internal/app           сборка зависимостей и роутер
internal/handler       HTTP: разбор запроса, валидация, маппинг в DTO
internal/service       бизнес-логика и правила доступа
internal/repository    SQL
internal/dto           запросы и ответы API
internal/model         доменные структуры
internal/apperr        доменные ошибки с кодами
internal/helper        JSON-ответы, разбор параметров, периоды, деньги
internal/middleware    авторизация, логирование запросов
```

Поток данных односторонний: `handler → service → repository`. Сервис не знает
про HTTP, репозиторий не знает про DTO.

### Решения, которые стоит знать

**Доступ.** Каждая запись принадлежит пользователю, и `user_id` из токена
подставляется в `WHERE` каждого запроса. Чужая запись отдаёт `404`, а не `403`:
существование чужих данных не подтверждается.

**Авторизация.** JWT HS256 со сроком 7 дней. Refresh-токенов нет: истёк —
логинимся заново. Отзыва отдельных токенов тоже нет; аварийный способ погасить
все выданные токены — сменить `JWT_SECRET` и перезапустить сервис. Смена пароля
через `useradm passwd` старые токены не убивает.

**Защита входа.** Rate limit по логину, а не по IP: после 5 неудачных попыток
вход по этому логину блокируется на 15 минут. Несуществующий логин отвечает тем
же кодом и за то же время, что и неверный пароль (сравнение идёт с
хешем-заглушкой) — иначе по разнице ответов перебираются валидные логины.

**Деньги.** `amount` хранится как `REAL` с ограничением `CHECK (amount > 0 AND
amount = ROUND(amount, 2))`. Что положили — то и достали: `123.45` остаётся
`123.45`. Суммы считает SQL (`SUM`, `GROUP BY`) — в Go траты циклом не
складываются: SQLite с версии 3.44 суммирует REAL компенсированным алгоритмом
(Kahan-Babuska) и даёт точный результат, а наивный цикл накапливает погрешность.

**Даты.** `spent_at` — календарная дата `YYYY-MM-DD`, а не момент времени. Учёт
ведётся по дням, и это снимает вопросы с таймзонами: «траты за 30 августа» —
это буквально `spent_at = '2026-08-30'`. Технические `created_at` / `updated_at`
хранятся в UTC в формате RFC3339.

**SQLite.** PRAGMA задаются в строке подключения, а не разовым `Exec`: они
действуют на соединение, а пул открывает новые соединения по мере надобности.
Особенно это важно для `foreign_keys` — иначе `ON DELETE RESTRICT` молча не
сработает на части запросов. Параметр `_txlock=immediate` нужен, чтобы
транзакция «сначала прочитал, потом пишу» не получала `SQLITE_BUSY_SNAPSHOT`,
который `busy_timeout` не лечит.

**Статика.** Фронтенд отдаёт сам сервис, catch-all маршрутом после всех
маршрутов API. Если файла нет — отдаётся `index.html`, чтобы прямой заход на
`/expenses` и перезагрузка страницы работали при History-роутинге. Запросы к
несуществующим путям под `/api/` этим фолбэком не перехватываются и возвращают
JSON-ошибку: иначе клиент получил бы HTML со статусом 200 вместо понятной 404.

Когда сверху встанет nginx, менять в Go ничего не нужно. Либо nginx отдаёт
статику сам (`try_files $uri /index.html`) и до Go запросы за файлами просто не
доходят, либо проксирует всё в Go и статику продолжает отдавать сервис.

**Удаление.** Мягкого удаления нет: удаление настоящее. Категорию с тратами
удалить нельзя — сервис проверяет это явным запросом и отдаёт `409`, а
`ON DELETE RESTRICT` в схеме остаётся страховкой на случай бага.

### Известные ограничения

- Сортировка категорий использует `COLLATE NOCASE`, который в SQLite
  регистронезависим только для латиницы. Для кириллицы «продукты» и «Продукты»
  считаются разными именами, и обе категории можно завести одновременно.
- WAL требует локальной файловой системы (не NFS) и создаёт рядом файлы
  `.db-wal` и `.db-shm`. Бэкап делать через `VACUUM INTO`, а не копированием
  одного `.db`.

## Тесты

```bash
go test ./...
```

Покрыто то, что реально ломается: границы периодов (неделя с понедельника,
февраль високосного года, переходы через границы месяца и года), округление
сумм, изоляция пользователей на каждой операции, запрет удаления категории
с тратами, блокировка входа после серии неудачных попыток, `CHECK`-ограничения
схемы. Репозитории тестируются на временном файле SQLite с накатыванием
настоящей миграции — не отдельного тестового DDL.
